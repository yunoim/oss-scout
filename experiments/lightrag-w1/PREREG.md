# 사전 등록 — LightRAG 1주차 (CEO-16)

질의를 하나도 돌리기 전에 커밋한다. 이 파일과 `questions.jsonl` 은 결과를 본 뒤 고치지 않는다
(고쳐야 하면 새 커밋에 사유를 적고, 결과표에 "사후 변경" 으로 표시한다).

## 물음
한국어 문서에서 LightRAG(지식그래프 RAG)가 **같은 로컬 LLM·같은 임베딩·같은 청크의 일반 RAG** 보다
정답률이 **+10%p 이상** 높은가. 높지 않으면 candidate-lightrag.md 의 판매 근거("한국어에서 더 잘 답한다")가 없다 → 중단.

## 고정 조건
| 항목 | 값 |
|---|---|
| 패키지 | `lightrag-hku==1.5.7` (전용 venv) |
| LLM | `qwen3:8b` (Ollama, Apache-2.0) · `think=false` · temperature 0 · seed 42 · `num_ctx` 12288 |
| 임베딩 | `bge-m3` (Ollama, 1024차원) |
| 인덱스 | 하나. 두 모드가 같은 청크·같은 그래프를 쓴다. `addon_params.language = Korean` |
| 질의 예산 | `max_total_tokens` 8000 (두 모드 공통), 리랭커 끔, 나머지는 1.5.7 기본값 |
| 문서 | 가평군 자치법규 7건(조례 4 · 시행규칙 3), 약 5.7만 자. 저작권법 제7조 비보호 저작물. 본업·사내 자료 0 |

- `qwen3:8b` 를 고른 이유: 상품 전제(고객 PC 에서 도는 로컬 모델)이고 상업 이용 가능한 라이선스. `exaone3.5` 는 비상업 라이선스라 뺐다.
- 알려진 한계: LightRAG 문서는 인덱싱 LLM 으로 더 큰 모델·긴 컨텍스트를 권한다. 8B·12k 는 그보다 작다 —
  결과가 "8B 로컬 조건에서의 LightRAG" 라는 점을 결론에 그대로 적는다. 12k 컨텍스트에서 qwen3 가 일부 CPU 로 넘친다(속도만 영향).
- 예산 8000 토큰은 코퍼스(청크 수 × 청크 크기)의 여러 분의 일이어야 한다 — 일반 RAG 가 코퍼스 전체를 보게 되면 비교가 무의미하다. 인덱싱 뒤 청크 수로 확인해 결과표에 적는다.

## 비교
- **주 비교: `mix` vs `naive`.** `mix` 는 1.5.7 `QueryParam` 의 기본 모드 — 상품이 그대로 내보낼 모드다.
- 참고: `hybrid` (그래프만, 청크 벡터 검색 없음).
- 참고: **무검색 기준선** — 같은 LLM 에 문서 없이 질문만. "사전학습에 없는 문서" 라는 전제를 직접 잰다.

## 평가셋 — `questions.jsonl` 30문항
- local 15(조문 하나) · multi 10(조문 둘 이상 또는 조례↔시행규칙) · global 5(문서 전반 종합, 필수 요점 목록 `points`)
- 문항·정답은 메인(Claude)이 문서를 읽고 썼다. 출제자 편향 가능성을 결과에 적는다.

## 채점
- 문항당 1 / 0.5 / 0. 정답 근거 문장 기준.
  - local·multi: 정답의 핵심 값이 모두 맞으면 1, 일부만 맞으면 0.5, 틀리거나 "모른다" 면 0. 정답 외에 **틀린 사실을 단정**하면 한 단계 내린다.
  - global: `points` 를 다 다루면 1, 절반 이상이면 0.5, 그 미만이면 0. 답을 거부하면 0.
- 채점자: Sonnet 하위 에이전트. 모드를 가린다(답변 순서 섞기 · 모드 이름·형식 표식 제거). 메인이 30×4 전부 다시 확인한다.

## 판정
- **주 지표: 30문항 전체 정답률(점수 합 ÷ 30).** 범주별 결과는 보조 — 그래프에 유리한 범주(multi·global)가 절반이라 그걸 주 지표로 삼지 않는다.
- **통과: `mix` − `naive` ≥ +10%p** (= 30문항에서 3점 이상).
- 문항별 승·패·무도 함께 적는다. n=30 이라 +10%p 는 3문항 차이다 — 경계에 걸리면 "경계" 로 적는다.

## 사전 수정 (2026-10-03, 질의 0건 상태)
- `num_ctx` 12288 → **8192**, 질의 예산 `max_total_tokens` 8000 → **5000** (두 모드 공통).
  사유: 10/3 PC 가 부하로 멈췄다. 12288 에서 qwen3:8b 가 13% CPU 로 넘쳐 시스템 RAM 을 썼다 — 8192 면 VRAM 에 다 올라간다. MLPC CEO 결정.
  더 작은 모델로 바꾸는 안은 RAM 효과가 같고 그래프 추출 품질만 떨어뜨려 기각.
- 색인 7건 중 앞 2건(2019599·2019600)은 12288 에서 만들어졌다. 추출 프롬프트(청크 1200 토큰 + 지시문)는 두 값 모두 안에 들어가 잘리지 않으므로 다시 만들지 않는다.
- 예산이 줄어 코퍼스 대비 비율이 더 작아졌다(일반 RAG 가 전체를 보는 문제에서 더 멀어짐). 실제 청크 수는 결과표에 적는다.
